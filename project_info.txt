PROJECT INFORMATION — SI EDUCATION (SEMANTIC WEB E-LEARNING PLATFORM)
================================================================================

1. GENERAL OVERVIEW
--------------------------------------------------------------------------------
Project Name : SI Education — Semantic Web Education & Training Platform
Domain       : E-Learning, Learning Paths, Academic Programs, Skills, Evaluations
               & Certifications
Core Concept : Full-stack Semantic Web application whose course catalog, guided
               learning paths (`ParcoursApprentissage`), actors, pedagogical
               programs, evaluations, and certifications are driven by an OWL 2
               Ontology authored in Protege (`education_formation_protege.owl`),
               stored in Apache Jena Fuseki with active OWL inference, and
               exposed through a FastAPI REST + SPARQL backend to two React/Vite
               web interfaces.

4. DATABASES USED IN THE PROJECT (HYBRID ARCHITECTURE)
--------------------------------------------------------------------------------
The platform uses TWO complementary databases:

A) Primary Semantic Database: Apache Jena Fuseki (TDB2 + OWL Inference)
   - Image / Port : `stain/jena-fuseki:latest` on `http://localhost:3030`
   - Dataset Name : `education` (configured in `fuseki/config.ttl`)
   - Storage      : Apache Jena TDB2 persistent triple store located at
                    `/fuseki/databases/education` (Docker volume `fuseki-data`).
   - OWL Reasoner : `http://jena.hpl.hp.com/2003/OWLFBRuleReasoner` (`ja:InfModel`)
                    mounted as the default graph over the TDB2 base model.
                    Enables automatic RDFS/OWL subclass deduction (e.g.,
                    `ParcoursDebutant` and `ParcoursAvance` individuals are
                    deduced as `edu:ParcoursApprentissage`; `Examen` and `Quiz`
                    are deduced as `edu:Evaluation`).
   - Stored Data  : All domain entities, semantic relationships, course catalog,
                    prerequisites, skills, programs, learning paths (`Parcours_Web`,
                    `Parcours_Data`, `Parcours_FullStack`), instructors, students,
                    evaluations, grades (`noteObtenue`), and certifications
                    (~1,772 RDF triples including inferred triples).

B) Secondary Relational Database: SQLite (`backend/data/utilisateurs.db`)
   - Engine       : Python built-in `sqlite3` (zero external DB server needed).
   - Tables       :
     1. `utilisateurs`          : User accounts, password hashes, roles, active flag.
     2. `quiz_questions`        : Multiple-choice questions linked to an OWL `Quiz` ID.
     3. `quiz_tentatives`       : Student quiz submissions, chosen answers, and scores.
     4. `parcours_cours_ordre`  : Ordered sequence `(parcours_id, cours_id, position)`
                                  complementing `edu:contientCoursParcours` (which
                                  remains the semantic membership truth in OWL).
     5. `parcours_inscriptions` : Student enrollments `(utilisateur_id, parcours_id,
                                  statut, cree_le, maj_le)`.
     6. `parcours_cours_suivis` : Tracks `edu:suitCours` triples added automatically
                                  upon path enrollment so unenrollment/deletion is
                                  cleanly reversible without touching unrelated courses.

C) Automatic Synchronization Between SQLite, Fuseki, and `.owl`
   - User Sync (`ontologie_sync.py` + `export_owl.py`):
     Maintains `edu:compte_<id>` in Fuseki and `education_formation_protege.owl`
     while preserving existing `<suitCours>`, `<suitFormation>`, and
     `<obtientCertification>` links.
   - Learning Path Sync (`routers/parcours.py` + `export_owl.py`):
     Every admin create/update/reorder/duplicate/delete updates Fuseki via SPARQL
     UPDATE, reconciles `parcours_cours_ordre` in SQLite, and atomically writes all
     `ParcoursDebutant`/`ParcoursAvance` individuals back to `education_formation_protege.owl`.
   - Enrollment `suitCours` Sync:
     Enrolling in a path adds `edu:suitCours` on the student's first uncompleted
     course in Fuseki + `.owl`; unenrolling removes it if no other active path uses it.


5. USER ROLES & PERMISSIONS (RBAC)
--------------------------------------------------------------------------------
Authentication uses signed Bearer tokens (`Authorization: Bearer <token>`,
shared between `:3001` and `:5173` via the `si-education-session` cookie).

1) `admin` (Administrator — default: `admin@si-education.tn` / `Admin@123`)
   - Full access to `/`, `/education`, `/parcours`, `/evaluations`, `/utilisateurs`.
   - Learning Paths (`/parcours`): full CRUD, course sequence reordering,
     duplication as draft, deletion with impact analysis, pedagogical coherence
     analysis with 1-click topological sort, and ApexCharts analytics.
   - Full CRUD on Users, OWL Evaluations, Quizzes, Certifications, and OWL reloads.

2) `formateur` (Instructor / Trainer)
   - Access to `/`, `/education`, `/parcours` (read-only table, roadmap detail,
     coherence analysis & statistics), and `/evaluations` (full CRUD on
     evaluations, quiz questionnaires, and certifications).

3) `etudiant` (Student / Learner)
   - Front-Office (`:3001`) & Learner Portal (`:5173/parcours`, `/evaluations`):
     browse published learning paths, enroll/unenroll, track derived per-course
     and global progress (`non_commence` / `en_cours` / `termine` computed from
     validated OWL evaluations), receive personalized path recommendations with
     explanations, and pass auto-graded quizzes.

4) Unauthenticated Visitor
   - Read-only access to published courses and learning paths on `:3001` (with
     redirect to login when clicking "S'inscrire").


6. ENTITIES & DATA MODEL (LEARNING PATHS FOCUS)
--------------------------------------------------------------------------------
- OWL Hierarchy:
  `edu:ParcoursApprentissage`
    |-- `edu:ParcoursDebutant` ("Parcours Débutant")
    `-- `edu:ParcoursAvance`   ("Parcours Avancé")
- OWL Object Property:
  `edu:contientCoursParcours` (`ParcoursApprentissage -> Cours`)
- OWL Data Properties (`xsd:string`):
  `edu:nomParcours` (required, unique case-insensitive)
  `edu:descriptionParcours`
  `edu:objectifParcours`
  `edu:statutParcours` (`brouillon` | `publie`)
- Seeded Learning Paths:
  1. `Parcours_Data`      (`ParcoursDebutant`, `publie`) : `Python` (30h)
  2. `Parcours_Web`       (`ParcoursDebutant`, `publie`) : `JavaScript` -> `Angular` (55h)
  3. `Parcours_FullStack` (`ParcoursAvance`, `publie`)   : `Python` -> `JavaScript` -> `Angular` (85h)


7. MAIN API ENDPOINTS (`/api`)
--------------------------------------------------------------------------------
Learning Paths (`/api/education/parcours`):
- `GET    /api/education/parcours`                     : Filtered/sorted list + aggregates
- `POST   /api/education/parcours`                     : Create path (admin)
- `GET    /api/education/parcours/mes-parcours`        : Enrolled paths & derived progress (etudiant)
- `GET    /api/education/parcours/recommandations`     : Personalized path recommendations (etudiant)
- `GET    /api/education/parcours/statistiques`        : Analytics & shared courses (admin/formateur)
- `GET    /api/education/parcours/proprietes-owl`      : OWL property declarations
- `GET    /api/education/parcours/{id}`                : Full path detail, ordered steps, enrollees/progress
- `PUT    /api/education/parcours/{id}`                : Update metadata, status & OWL level class (admin)
- `PUT    /api/education/parcours/{id}/cours`          : Replace/reorder full course sequence (admin)
- `POST   /api/education/parcours/{id}/cours`          : Insert single course at position (admin)
- `DELETE /api/education/parcours/{id}/cours/{coursId}`: Remove single course from path (admin)
- `POST   /api/education/parcours/{id}/dupliquer`      : Duplicate path as draft (admin)
- `DELETE /api/education/parcours/{id}`                : Delete path from Fuseki, `.owl` & SQLite (admin)
- `GET    /api/education/parcours/{id}/analyse`        : Coherence analysis & Kahn topological sort
- `POST   /api/education/parcours/{id}/inscription`    : Enroll student & sync `suitCours` (etudiant)
- `DELETE /api/education/parcours/{id}/inscription`    : Unenroll student & clean `suitCours` (etudiant)

Other Core Endpoints:
- Auth & Users : `/api/auth/inscription`, `/connexion`, `/moi`, `/utilisateurs`, `/synchroniser`
- Education    : `/api/education/sante`, `/cours`, `/etudiants`, `/formateurs`, `/formations`,
                 `/competences`, `/programmes`, `/statistiques`, `/hierarchie`, `/types-inferes`
- Assessments  : `/api/education/evaluations`, `/mes-evaluations`, `/certifications`, `/quiz/{id}...`
- Ontology     : `/api/ontologie/charger`, `/televerser`, `/prerequis-competences`
